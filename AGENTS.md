# AGENTS.md

Instructions for AI coding agents (Claude Code, Cursor, etc.) working
*on* this repo. If you're looking for docs on *using* quiz-ui in another
project, see `public/llms.txt` or `content/docs/` instead — this file is
for contributors to quiz-ui itself.

## Repo shape

```
app/                     Next.js site (docs + home + /example) — not part of the registry
components/ui/quiz/      registry source — this IS what ships to consumers
  core/                  headless engine: types.ts, engine.ts, QuizProvider.tsx, hooks.ts
  quiz-*.tsx             styled components, one per file
lib/utils.ts             cn() helper
hooks/                   site-chrome hooks only (not registry hooks — those live in core/)
config/site.ts           docs-site nav/metadata
content/docs/            MDX docs, one file per component + getting-started.mdx
registry.json            hand-maintained manifest — source of truth for `pnpm registry:build`
public/r/                generated by `pnpm registry:build` — do not hand-edit
public/llms.txt           consumer-facing AI index — keep in sync with registry.json
db/, server/              site-backend stubs, currently empty (see their README.md)
```

## Rules when adding or editing a component

1. Component source lives in `components/ui/quiz/<name>.tsx`. Read a
   neighboring component first — every component follows the same shape:
   `"use client"` directive at the top (every component and core file
   uses React state/context — see note below), Radix primitive
   underneath, styled with Tailwind + CVA, answer state read/written via
   `useQuizAnswers()` (never `value`/`onChange` props — see any existing
   component for the pattern).
2. Naming is `Quiz<Noun>` for components, `useQuiz<Noun>` for hooks. No
   abbreviations, no exceptions — this repo's whole "AI-friendly" premise
   depends on the convention actually being followed everywhere.
3. New component → also add:
   - an entry to `registry.json` (`files`, `dependencies`,
     `registryDependencies`, `description`)
   - a page at `content/docs/components/<name>.mdx`
   - a line in `content/docs/components/meta.json`
   - a line in `public/llms.txt`
4. After any change to `components/ui/quiz/` or `registry.json`, run
   `pnpm registry:build` before committing — `public/r/*.json` is
   generated, and a stale build means the CLI ships old code to consumers.
5. Branching logic belongs in `components/ui/quiz/core/engine.ts`
   (data-driven, via `QuizDefinition.steps[].branch`), never hardcoded
   inside a component. If a component-specific behavior feels like it
   needs to know about *other* steps, that's a sign it belongs in the
   engine instead.
6. Don't add `value`/`onChange` props to answer components — they read
   the current step's answer via `useQuizAnswers()` automatically. This
   is deliberate (see the header comment in `core/types.ts`) and breaking
   it breaks the "a QuizDefinition is just data" property the whole
   engine relies on.
7. Every file under `components/ui/quiz/` (including `core/`) needs
   `"use client"` as its first line — this is a client-only library
   (React context, state, event handlers), and Next.js App Router treats
   every component as a Server Component unless told otherwise. If a page
   that renders `<QuizRoot>` also defines an inline callback (e.g.
   `onComplete`) and that page itself has no `"use client"` directive,
   you'll hit "Event handlers cannot be passed to Client Component
   props" — the fix is adding `"use client"` to the *page*, not the
   library.

## Commands

```bash
pnpm install
pnpm dev              # run the docs/demo site
pnpm registry:build   # regenerate public/r/*.json from registry.json (runs `shadcn build`)
pnpm typecheck
```
